# Step 15 手動確認チェックリスト（デザインとダークモード）

自動テスト（`scripts/check/web.sh` の #2・#3）では、次を検証している: 色がデザイントークン以外に書かれていないこと、両方のテーマで
文字と背景のコントラスト比が 4.5:1 以上（枠線・フォーカスは 3:1 以上）であること、`index.html` のスクリプトの置き場所と規則、ビルド。
**目で見る確認**（見た目・ちらつき・OS 設定への追従・各画面）は、このチェックリストで行う。
各項目は、確認できたら `[x]` にする。**ライトとダークの両方で、同じ画面を確認すること**（各項目の後ろの ☀ / 🌙 を、順に確認する）。

## 0. 準備

- [ ] 前提: [environment.md](environment.md) の手順で Rust と Trunk が入っている
- [ ] 小さな選挙データを生成する（有権者 `voter-1`〜）:
  ```
  cargo run -q -p seedgen -- --out /tmp/seed-demo --election-id 2026-general --prefectures 3 --districts-per-pref 2 \
    --candidates-per-district 4 --voters 30 --municipalities-per-pref 2 --pref-assembly-districts-per-pref 2 --force
  ```
- [ ] 起動して、投票の受付を始める（ブロックが見られるよう、3 票ごとに封印する）:
  ```
  APP__ELECTION__SEED_DIR=/tmp/seed-demo APP__SEAL__MAX_BALLOTS=3 scripts/dev_up.sh   # 画面 http://localhost:8080
  scripts/election.sh open --now --yes
  ```
- [ ] 開発者ツール（F12）を開き、Console にエラーが出ていない
- [ ] （任意）OS の設定で、ライト / ダークを切り替えられるようにしておく

## 1. 切り替えボタン（ヘッダー）

- [ ] ヘッダーに「ライト」「ダーク」「OSに合わせる」の 3 つのボタンがある
- [ ] 選択中のボタンは、**色の違いだけでなく**、先頭の「✓」・太い枠・太字で分かる（色覚特性のシミュレーションや、白黒表示でも区別できる）
- [ ] 「ダーク」を押すと、すぐに、全体がダークになる。「ライト」を押すと、白基調に戻る
- [ ] 「OSに合わせる」を押すと、OS の現在の設定（ライト / ダーク）になる
- [ ] Tab キーだけで 3 つのボタンに移動でき、Enter / Space で切り替えられる。フォーカスの枠が見える
- [ ] 画面幅を狭くしても（スマートフォンの幅）、ヘッダーが崩れない（ボタンが折り返す）

## 2. 初回の表示と、選択の保存

- [ ] 開発者ツール › Application › Local Storage で、`theme` を削除して再読み込みすると、**OS の設定**に従う
- [ ] 「ダーク」を選んで再読み込みしても、ダークのまま（Local Storage の `theme` が `dark`）。「ライト」は `light`、「OSに合わせる」は `system`
- [ ] **ちらつきがない**: ダークを選んだ状態で再読み込み（強制再読み込み: Ctrl+Shift+R）しても、白い画面が一瞬でも表示されない
      （開発者ツールの Network で「Slow 3G」にして、読み込み中の背景色も見る。ライトで再読み込みしても、暗い画面が一瞬でも出ない）
- [ ] `theme` に `foo` のような不正な値を入れて再読み込みしても、OS の設定に従い、画面は壊れない
- [ ] 「OSに合わせる」を選んだまま、OS の設定（ライト / ダーク）を切り替えると、**再読み込みなしで**追従する
- [ ] 「ライト」または「ダーク」を選んでいるときは、OS の設定を切り替えても、変わらない
- [ ] （任意）ブラウザのプライベートウィンドウでも、画面が壊れない（保存できなくても、その画面では切り替わる）
- [ ] ログアウトしても、テーマの選択は残る（テーマは、セッションではなく、ブラウザの設定）。トークンや投票の内容は、どこにも保存されていない
      （Local Storage には `theme` だけ。Application › Storage を確認する）

## 3. 各画面（ライト ☀ / ダーク 🌙 の両方）

### 3-1. ログイン画面（`/`）
- [ ] ☀ 白基調。見出し・ラベル・入力欄・ヒントの文字が読める。入力欄の枠がはっきり見える
- [ ] 🌙 暗い背景に、明るい文字。入力欄・ボタンが背景から区別できる
- [ ] 何も入力せずに「ログイン」を押すと、エラーの文言の先頭に「⚠」が付く（赤系の色だけに頼っていない）。☀ / 🌙 とも読める
- [ ] ログイン ID 入力欄をクリックしたとき、フォーカスの枠が見える

### 3-2. 進捗の画面（`/progress`）
- [ ] ☀ / 🌙: 各行の状態が、「✓ 済み」「▶ 今」「○ これから」と、記号と文字で分かる（色だけではない）
- [ ] ☀ / 🌙: 「今」の行は、左の太い線と薄い背景でも区別できる。「済み」は、緑系の色に加えて太字
- [ ] 「続ける」ボタンの文字が読める

### 3-3. 投票画面（候補者の選択）
- [ ] ☀ / 🌙: 候補者が、枠つきの行で並ぶ。氏名と政党（薄い色）が読める
- [ ] 候補者を選ぶと、その行が、**太い枠・太字・右端の「✓ 選択中」・薄い背景**になる（枠の色だけの違いではない）。選び直すと、前の行の表示が消える
- [ ] 何も選ぶまで「確認へ進む」が押せない（無効のボタンが、無効と分かる）
- [ ] キーボード（矢印キー・Tab）で候補者を選べて、フォーカスの枠が見える

### 3-4. 確認画面
- [ ] ☀ / 🌙: 「選んだ候補者」の文字が大きく読める。「戻る」（枠だけのボタン）と「投票する」（塗りのボタン）が、区別できる
- [ ] 送信に失敗させる（api を止めてから「投票する」）と、「⚠」つきのエラーが表示される。☀ / 🌙 とも読める

### 3-5. 完了画面（`/done`）
- [ ] ☀ / 🌙: 「投票を受け付けました」が中央に大きく表示され、読める

### 3-6. ブロックチェーンのビューア（`/chain` 以下）
- [ ] ☀ / 🌙: シャードの一覧・ブロックの一覧・ブロックの詳細（項目名は薄い色、値は通常の色）・票の一覧の表・アンカーの一覧が読める
- [ ] ☀ / 🌙: リンク（下線つき）が、本文と区別できる。ハッシュ（等幅フォント）が読める
- [ ] ☀ / 🌙: 「このチェーンを検証するには」のコマンド欄（淡い背景）が、周りと区別できて、文字が読める
- [ ] ☀ / 🌙: 「さらに古いブロックを表示」ボタン（枠だけ）が見える
- [ ] 存在しないブロック（`/chain/0/blocks/9999`）の「⚠ 見つかりません。」が読める
- [ ] 画面幅を狭くしても、ハッシュや表がはみ出さない

## 4. 全体の品質

- [ ] ☀ 背景は**白**（ページもカードも白。カードは淡い灰色の枠線で区別される）。ヘッダーだけが、ごく淡い灰色
- [ ] どの画面でも、テーマを切り替えたとき、**一部だけ色が切り替わらない箇所**（白いままの部品、暗いままの部品）がない
- [ ] 入力欄・ラジオボタン・スクロールバーなどのブラウザ部品も、ダークのときは暗い配色になる
- [ ] ブラウザの拡大（200%）でも、レイアウトが崩れない
- [ ] （任意）ブラウザの開発者ツール（Lighthouse の Accessibility、または Chrome の「コントラスト比」表示）で、
      コントラストの指摘が出ない
- [ ] （任意）OS の「コントラストを上げる」「透明度を下げる」などの設定でも、読める
