# Step 5 手動確認チェックリスト（画面）

自動テスト（`scripts/check/web.sh`）では、画面遷移ロジックとビルドまでを検証している。
ブラウザでの見た目・操作・秘密投票の性質は、このチェックリストで確認する。
各項目は、確認できたら `[x]` にする。

## 0. 準備

- [ ] 前提: [environment.md](environment.md) の手順で Rust と Trunk が入っている
- [ ] 起動して、投票の受付を始める（起動直後の選挙状態は scheduled で、投票を受け付けない）:
  ```
  scripts/dev_up.sh
  scripts/election.sh open --now --yes
  ```
  （api 18080・画面 8080。封印は、未封印が 10 件以上で 10 秒ごと（`config/dev.toml`）。1 票から封印を確かめたいときは、
  `APP__SEAL__MIN_BALLOTS_AFTER_INTERVAL=1 scripts/dev_up.sh` で起動する）
- [ ] ブラウザで http://localhost:8080 を開く。ログイン画面が表示される
- [ ] 開発者ツール（F12）を開き、Console にエラーが出ていない

## 1. ログイン

- [ ] 何も入力せず「ログイン」→「投票者 ID を入力してください。」と表示される（サーバへは送られない）
- [ ] `a.b` や `日本語` → 使える文字についての案内が表示される
- [ ] 65 文字以上 → 「64 文字以内」の案内が表示される
- [ ] マイナンバー欄は入力が伏せ字（`•••`）になる。欄の下に「使われず、保存もされません」と書かれている
- [ ] `alice`（サンプルの選挙データの、東京 1 区の有権者）でログインすると、先頭の未投票の投票用紙（東京 1 区の小選挙区）の投票画面へ自動で進む（ログイン後、マイナンバー欄は空になっている）。選挙データの有権者でない ID では、「投票できる投票用紙がありません」の進捗画面になる

## 2. 進捗の画面（投票する順番は固定）

- [ ] 投票画面の上に「9枚中1枚目」と表示される（`labels.progress` の型。`alice` は 9 枚）。「進捗を見る」で進捗の画面に移る
- [ ] 進捗の画面には、`alice` に関係する 9 枚だけが、表示順（小選挙区 → 比例代表 → 参議院選挙区 → …）に並び、
      先頭に「今」、残りに「これから」と表示される（投票済みは「済み」）。**リンクはない**（順番は選べない）
- [ ] 「続ける」を押すと、「今」の投票用紙の投票画面に移る
- [ ] 投票画面の URL（`/ballots/2026-general/…`）を手で書き換えて、まだ先の投票用紙を開こうとしても、
      「今」の投票用紙へ戻される
- [ ] ヘッダの「ログアウト」でログイン画面に戻る。再ログインすると、先頭の未投票の投票用紙から再開する

## 3. 投票（1 件目）

- [ ] 候補者がラジオボタン（氏名と政党）で表示される（東京 1 区は 4 名）。何も選ぶまで「確認へ進む」は押せない
- [ ] 候補者を選び直せる（最後に選んだものだけが選択状態になる）
- [ ] 「確認へ進む」→ 確認画面に「「（選んだ候補者名）」に投票します。よろしいですか？」と表示される
- [ ] 「戻る」→ 選択画面に戻り、先ほどの選択が保たれている
- [ ] もう一度「確認へ進む」→「投票する」→ 一瞬「送信中です…」の後、完了画面に移る

## 3a. 白票（ADR 0021）

- [ ] 候補者一覧の**最後**に「白票（どの候補者にも投票しない）」（`labels.blank_option`）があり、候補者とは余白と破線の枠で区切られている
- [ ] 白票を選ぶと、ほかの候補者と同じく、太い枠・太字・「✓ 選択中」で選択中と分かる（破線は実線に変わる）
- [ ] 「確認へ進む」→ 確認画面に「白票として投票します。よろしいですか？」（`labels.blank_confirm`）と表示される
      （「「白票（…）」に投票します」のような、候補者名の型にはならない）
- [ ] 「投票する」→ 完了画面は、候補者に投票したときと同じ（「投票を受け付けました」だけ）
- [ ] 票が封印された後、ビューア（`/chain` → ブロックの詳細）で、その票の「投票先」が「白票」（`labels.blank_name`）と斜体で表示され、
      「このブロックの投票先別の票数」では、候補者の行の後に、白票が別の行で表示される
- [ ] API を `APP__VOTE__ALLOW_BLANK=false` を付けて起動し直すと（memory モードは再起動で選挙状態も作り直されるので、
      新しい設定の値が open の時点で固定される）、候補者一覧に白票の選択肢が出ない

## 3b. 投票のやり直し（再投票。ADR 0022）

準備: `config/local.toml` に `[vote]` の `allow_revote = true`・`max_revotes = 2` を書いて `scripts/dev_up.sh` で起動する
（`secrets/revote_key` が無ければ、dev_up.sh が作る）。

- [ ] 確認画面の注意書きが「投票期間内なら、この後あと 2 回やり直せます。」になる（再投票を認めない選挙では「やり直しはできません」）
- [ ] すべての投票用紙に投票すると、完了画面に「投票をやり直す」（`labels.revote_button`）が出る。途中の投票用紙の完了画面には出ない
- [ ] 「投票をやり直す」→ 投票済みの投票用紙が、表示順（固定）で並ぶ。**前回の投票先はどこにも表示されない**。各行に「やり直す（あと N 回）」
- [ ] 1 枚を選ぶ → 候補者を選ぶ → 確認画面の先頭に「前回の投票内容を変更します」（`labels.revote_confirm`）→「投票する」→ 完了画面
- [ ] 同じ投票用紙を 2 回やり直すと、その行のボタンが押せなくなり、「⚠ やり直しの上限（2回）に達しています」と表示される
- [ ] 開発者ツールの Network で、やり直しの本文が `{"candidate_id": …, "revote": <見た票の数>}` で、応答に投票内容が含まれない
- [ ] 2 つのタブで同じ投票用紙のやり直し画面を開き、両方で「投票する」→ 後のほうは、やり直しの一覧に戻って「別の画面からのやり直しが
      先に受け付けられました」と表示される
- [ ] `scripts/election.sh close --now` の後は、完了画面・一覧に、やり直しのボタンが出ない（「現在、投票のやり直しは受け付けていません」）。
      `secrets/revote_key` が消えていて、`scripts/election.sh status` の監査ログに `revote_key_destroyed` が出る
- [ ] 締切後、ビューア（`/chain` → ブロックの詳細）で、やり直した票に「#<前の票> を置き換え（A→B）」のリンクが出て、押すと前の票の行へ移る

## 4. 完了画面（秘密投票の要）

- [ ] 表示は「投票を受け付けました」**だけ**（ヘッダのサイト名とボタンを除く）
- [ ] 候補者名・投票用紙の名前・ID・「封印」「検証」などの文言が**どこにもない**
      （開発者ツールの Elements で `候補者`・選んだ名前を検索してもヒットしない）
- [ ] 完了画面の URL は `/done` で、候補者や投票用紙の情報を含まない
- [ ] ブラウザの「戻る」を押しても、投票画面（確認画面）には戻れない
- [ ] ボタンは「次の投票用紙へ」になっている

## 5. 続けて投票する（表示順に、先頭の未投票へ）

- [ ] 「次の投票用紙へ」→ 比例東京ブロックの投票画面（「9枚中2枚目」。表示順で次の未投票）
- [ ] 同様に、参議院選挙区 → 参議院比例代表 → 知事 → … の順に進む。**前に戻る・選べる**操作はない
- [ ] 最後の投票用紙（最高裁判所裁判官国民審査）を投票した後の完了画面のボタンは「終了」になっている
- [ ] 「終了」→ ログイン画面に戻る（セッションが破棄されている）

## 6. 再ログインと投票済みの扱い

- [ ] 同じ `alice` でログインし直すと、すべて投票済みなら進捗の画面に移り、「すべての投票用紙に投票済みです。」と表示される
      （途中までなら、先頭の未投票の投票用紙から再開する）
- [ ] 進捗の画面に「続ける」ボタンがない（未投票がないとき）
- [ ] 別の有権者（`bob` = 大阪 1 区）でログインすると、大阪の投票用紙 9 枚だけが表示される（`alice` の状態や東京の投票用紙が混ざらない）

## 7. エラー系

- [ ] **二重投票（409）**: 同じ ID で 2 つのタブにログインし、片方で第1区に投票 →
      もう片方（まだ選択画面のまま）で同じ投票用紙に投票すると、先頭の未投票へ移り
      「この投票用紙にはすでに投票済みです。」の案内が出る（完了画面にはならない）
- [ ] **セッション切れ（401）**: API を `APP__SESSION__TTL_SECS=30` 付きで起動し直し、ログインして 30 秒以上待ってから
      操作すると、ログイン画面に戻り、有効期限切れの案内が出る
- [ ] **API 停止**: 確認画面で API を止めてから「投票する」→
      「サーバに接続できませんでした。もう一度お試しください。」と表示される。
      API を再起動して「もう一度試す」を押すと、確認画面に戻って投票できる
      （API を再起動するとメモリ上の票は消える。トークンは同じ `session.secret` なら有効）
- [ ] **リロード**: どの画面でもリロードするとログイン画面に戻る（セッションはメモリのみ）
- [ ] **存在しない URL**（例: `/nothing`）→「ページが見つかりません」と表示される

## 8. 秘密投票の確認（開発者ツール）

- [ ] **Application → Local Storage / Session Storage / Cookies** が空（トークンも候補者も保存されていない）
- [ ] **Network** で投票のリクエスト（`POST /api/v1/contests/2026-general/shugiin_smd.13.01/vote` など）を開く:
  - [ ] リクエスト本文は `{"candidate_id": "shugiin_smd.13.01.c1"}` の形のみ（白票は `"blank"`。再投票のときだけ `revote` が付く）
  - [ ] 応答は `201` で本文は `{"status":"accepted"}` のみ（`ballot_id` などのレシートがない）
- [ ] **Console** にトークン・候補者・投票内容が出力されていない
- [ ] 投票の後、ブラウザの履歴（戻るボタンの長押し）に投票画面のエントリが残っていない
- [ ] api のログ（`logs/api.log`）に、投票者 ID も候補者も出ていない

## 9. プロキシ（開発時）

- [ ] Network タブで、API のリクエスト先が `localhost:8080`（画面と同じオリジン）になっている
- [ ] CORS エラーが出ていない
- [ ] `trunk serve` を止めずに api だけ再起動しても、画面から再び API を呼べる

## 10. 操作性・表示

- [ ] マウスを使わず、Tab / Space / Enter だけでログイン〜投票完了まで操作できる。フォーカスの位置が見える
- [ ] 画面幅 375px 程度（開発者ツールのデバイス表示）で、ボタンが押しやすく、横スクロールが出ない
- [ ] OS をダークモードにすると、配色が切り替わり、文字が読める

## 11. 任意: 封印との連携

- [ ] `curl http://localhost:18080/debug/pool` の `total` が、画面から行った投票数と一致する
- [ ] `APP__SEAL__INTERVAL_SECS=10 APP__SEAL__MIN_BALLOTS_AFTER_INTERVAL=1` で API を起動して投票し、10 秒ほど後に
      `cargo run -q -p verifier -- verify --api http://localhost:18080` が「検証 OK」になる
      （完了画面の文言は「受け付けました」のみで、封印の完了とは無関係であることも確認する）
