# 0016: 集計（verifier tally）

> 追記（[ADR 0019](0019-election-lifecycle.md)）: 前提確認の 3 番目（締切=時刻による判定）は、選挙状態
> （`ElectionPhase`。`closed` かどうか）による判定に置き換えた。`--allow-interim` は `app.env=dev` のときだけ。
> 以下の「決定」は、置き換え前の記述として残す。
> 追記（[ADR 0020](0020-seal-policy-min-ballots.md)）: 「締切フラッシュ = sealer の正常停止（SIGTERM）」は廃止した。残りの票は、
> 締切の手続き（選挙状態 closing）の中でだけ封印する。未封印が残っているときの案内も、closed を待つよう改めた。

## 背景
チェーン（封印済みのブロック）と participation（投票済み記録）はあるが、選挙区・都道府県・選挙の種類ごとの得票を出す手段がなかった。
集計は、改ざんされたデータや、まだ封印されていない票を含んでいてはならず、締切前の集計は途中経過の漏洩になる（原則 14）。

## 決定
- **場所**: `verifier tally`（`scripts/tally.sh` は薄いラッパー）。verifier は api の公開 API（`chains/{shard}/blocks`・
  `audit/counts`）だけを読むので、DB に直接つながない。集計に使う票は、**検証したブロックの票そのもの**（`ShardReport::votes`）。
  検証と集計で同じデータを使うので、間に票が入っても、食い違ったデータを集計しない（突合が不一致になり、中止する）。
- **前提の確認（順序固定。通らなければ集計せず、出力ファイルも作らない）**:
  1. `verify_all`（全シャードのチェーン検証）と `audit`（投票用紙別の突合・`ballot_id` の重複・アンカー）— 失敗は終了コード 3。
  2. 未封印の票が 0 件 — 残っていれば件数を表示して中止（4）。`--allow-interim` でも通さない（未封印の票は、チェーンで守られていない）。
  3. `election.voting_closes_at` 以後 — 前、または未設定なら、`--allow-interim` がなければ中止（4）。未設定を「締切前」と同じにするのは、
     安全側に倒すため（締切を決めないまま確定した集計を出さない）。
  純粋関数（`tally::gate::check`）で、時刻は引数で受け取る（原則 9 と同じ方針）。
- **締切フラッシュ**: 新しい操作は作らず、既存の「sealer の正常停止（SIGTERM）で残りをすべて封印」を使う。時刻に達したら自動で
  フラッシュする機能や、締切後の投票の拒否は、この版にはない。`election.voting_closes_at` の「未実装」を外し、今は tally だけが使う。
- **白票（無効票）**: 選挙区の候補者ではない票。白票を投じる手段は作らない（今は通常 0）。選挙データに無い投票用紙の票がチェーンに
  あれば、集計しない（3）。→ **ADR 0021 で置き換えた**: 白票は、票の `candidate_id` が予約値 `blank` の票で、候補者とは別に数える。
  投票用紙の候補者でも白票でもない票があれば、集計しない（3）。
- **都道府県別**: 単独の都道府県の選挙区はその都道府県へ。複数の都道府県にまたがる選挙区（合区・比例ブロック・全国）は、按分できないので
  選挙区ごとに 1 行。都道府県別・選挙の種類別の「投票済み数」は、投票用紙の枚数（秘密投票のため、重複を除いた人数は出せない）。
- **出力**: 表（全角を表示幅 2 で整列。選挙区ごとの表は既定で先頭 30 件、`--all` で全件）と、`out/tally/{日時（UTC）}/` の
  `districts.csv`・`candidates.csv`・`prefectures.csv`・`types.csv`・`reconciliation.csv`・`tally.json`。ディレクトリ・ファイルは
  `create_new` で作り、上書きしない。日時は、タイムゾーンで名前が変わらないよう UTC。表示名は seed と `labels.ballot_item`。
- **依存**: 新しいクレートは追加しない（verifier が、ワークスペースの `csv`・`serde_json`・`seed` を使うようになっただけ）。

## 理由
- 検証済みのブロックから集計すれば、「検証したデータ」と「集計したデータ」が一致する。
- 前提の確認を tally の中に持てば、別のスクリプトの呼び忘れで、未検証のデータを集計することがない。

## 代替案
- api に集計用のエンドポイントを足す: 投票期間中の集計の公開（原則 14）に近づくので不採用。
- DB を直接集計する: チェーンの検証を通らないデータを集計できてしまうので不採用。
