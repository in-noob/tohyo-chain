# 0004: 投票フローと秘密投票の担保（保存・シャード・セッション）

## 背景
Step 3 で、ログイン → 状態取得 → 候補者取得 → 投票 → 二重投票拒否 までの API を実装する。
封印処理は未実装で、未封印の票を「プール」に溜めるところまで。
原則1（投票者と投票内容を結び付けない）・原則6（API はステートレス）・原則7（認証はスコープ外）を守る必要がある。

## 決定
- **participation と ballot_pool を別データにする**（`VoteStore` の契約）。
  participation は「投票者 → 投票済みコンテスト集合」だけを持ち、ballot_id・候補者・時刻・到着順を持たない。
  ballot_pool は `(コンテスト, Ballot)` をシャードごとに到着順で持ち、投票者を特定する情報を持たない。
  両者を結ぶキーは存在しない。二重投票の判定と両方への追加は `cast` の中で不可分に行う。
- **`ballot_id` は乱数（UUIDv4）で、投票のたびに新規採番**する。投票者とは無関係。
- **シャードは `ballot_id` から決める**（`shard_for`）。`voter_id` から決めるとシャードが投票者と結び付くため。
  （[ADR 0022](0022-revote.md) で、再投票を認める選挙だけ、再投票の仮名 slot から決めるように変えた。slot は鍵の無い者には
  投票者に戻せない HMAC で、鍵は締切の手続きで破棄する。）
- **投票の 201 応答にレシートを含めない**（`{"status":"accepted"}` のみ）。ballot_id を返すと、
  買収・強要の場面で「誰に投票したか」の証拠として使えてしまう。
- **ログに投票者・候補者を出さない**。投票処理のログはコンテスト ID のみ。`Debug` 実装は件数だけを出す
  （ストア）か、機密を伏せる（マイナンバー、署名鍵）。統合テストとスクリプトでサーバログに投票者 ID が出ていないことを確認する。
- **セッションは HMAC-SHA256 署名トークン**: `v1.<voter_id>.<exp>.<base64url(tag)>`。署名を先に定数時間で検証してから
  期限を見る。署名鍵は `SESSION_SECRET`（16 バイト以上・全インスタンス共通）で、**未設定なら起動を拒否**する。
  時刻は `Clock` トレイトで注入する。
- **認証は `Authenticator` トレイト + `StubAuthenticator`**: 入力 ID を `voter_id` として採用し、マイナンバー欄は受け取って破棄する。
- **ポートはトレイト（`async-trait`）で、`Arc<dyn Trait>` として api が組み立てる**。DB 導入時に実装だけを差し替える。
- **`GET /debug/pool` は feature "dev-tools" のときだけ存在する**（ルートごとコンパイル対象外）。返すのは件数のみ。
- 全コンテストとも「1 人 1 票、候補者を 1 人選ぶ」に単純化する（国民審査の実際の様式は再現しない）。
  `candidate_id` は選挙内で一意にする。

## 理由
- 分離した 2 つのデータと、`ballot_id` に依存するシャードにより、保存データだけからは
  「誰がどの候補者に投票したか」を復元できない（時刻も保存しない）。
- 署名付きトークンにすると、サーバ側にセッション表を持たずに済み、水平スケールで任意のインスタンスが検証できる。
- 未設定時にランダム鍵へフォールバックすると、複数インスタンスでトークンが通らない不具合が黙って発生するため、起動時に失敗させる。

## 代替案
- **participation に ballot_id を持たせて重複検出**: 2 つのデータを結べてしまうため不採用。
- **`voter_id` のハッシュでシャード分割**: 投票者ごとにシャードが固定され、シャード内の件数推移が投票者に結び付くため不採用。
- **レシート（ballot_id）を返して後で包含証明を確認できるようにする**: 検証性は上がるが、買収・強要への耐性（レシートフリー）を損なう。
  検証は封印済みブロックの公開（verifier）で行う方針。
- **サーバ側セッション表（メモリ・DB）**: 原則6に反するため不採用。

## 留意点（暫定）
- インメモリの `VoteStore` は API プロセスのメモリに票を持つため、複数インスタンス間では共有されない。
  ScyllaDB 導入後に、`participation` は LWT（`IF NOT EXISTS`）で同じ契約を満たす実装に差し替え、水平スケールを検証する。
- 選挙の開始・締切、投票者の有権者名簿の検証は未実装。
