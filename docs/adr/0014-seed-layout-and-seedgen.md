# 0014: 選挙データの構成（seed/<election_id>/）・有権者名簿・seedgen・投票順の固定

## 背景
選挙マスタは `seed/election.json`（3 件の投票用紙・候補者 3〜5 人）だった。47 都道府県・複数の選挙の種類・候補者 1 万人以上を
扱うには、表計算ソフトで編集できる形式、読み込み時の厳密な検証、有権者ごとに関係する投票用紙だけを見せる仕組み、
規模を指定できるダミーデータの生成が要る。また、利用者が投票する順番を選べないようにする。

## 決定
- **ファイル構成**: `seed/<election_id>/` に、`election.toml`（選挙の定義・選挙の種類: code・表示名・表示順 `order`・
  投票方式 `method`（今は `single_choice` だけ。将来の拡張に備えて `enum`））、`districts.csv`（district_id・election_type・
  name・prefectures・order）、`candidates/<election_type>.csv`（candidate_id・district_id・name・party・profile）、
  `voters.csv`（voter_id・districts）。CSV は UTF-8・ヘッダ行あり・列の順序は問わない（BOM・前後の空白・空行も許す）。
  どの選挙を読むかは設定 `election.seed_dir` / `election.election_id`（ディレクトリ名と `election.toml` の `id` は一致させる）。
- **検証は Rust**（`crates/seed`）。JSON Schema は使わない: CSV・TOML をまたぐ整合（存在しない選挙区・種類の参照、ID の重複、
  同じ種類の選挙区が複数ある有権者、候補者のいない選挙区）は、スキーマでは書けない。エラーは、ファイル・行・原因つきで、
  最大 30 件まとめて報告する（それ以上は件数のみ）。`domain::Election::new` も同じ不変条件を再検査する。
- **有権者名簿**: `voters.csv` を、起動時に読み込み、読み取り専用のキャッシュとして持つ（`application::VoterRoll`。原則 6 の
  例外）。**メモリ・DB のどちらのモードでも**このファイルから読む（`auth.mode=db` のときだけ、名簿は DB の `voter_roll` から読む: [ADR 0015](0015-credentials-and-db-auth.md)）。
  名簿に無い有権者は、ログインできる（原則 7: stub 認証は入力 ID を採用する）が、投票用紙は 1 枚もなく、投票は 403 になる。
- **API**: `GET /api/v1/ballot-status`（有権者に関係する投票用紙だけを、表示順で返す）、
  `/api/v1/contests/{election_id}/{district_id}/{candidates|vote}`（対象外は 403、`contest` はパスのまま: 原則 12）。
  エラー応答に、利用者向けの `message` を足した。呼び名（`labels.ballot_item`）を含む文言は、ミドルウェアが、アプリケーション
  状態の設定から組み立てる（ハンドラは、エラーの種類だけを返す）。
- **投票順の固定**: 表示順は、選挙の種類の `order`、次に選挙区の `order`（同順なら ID の辞書順）。画面の `flow` は、
  一覧の先頭の未投票を「今」とし、投票後は先頭の未投票へ進む（前に戻る・最後まで行ったら最初へ折り返す動きは削除した）。
  投票画面に入れるのは「今」の投票用紙だけ（URL を書き換えても戻される）。進捗の画面は表示だけ（リンクなし）。
  **サーバは順番を強制しない**（`ballot-status` の並びと画面で担保）。強制は、対象外の投票（403）と二重投票（409）だけ。
- **`seedgen`**: 都道府県数・小選挙区の数・候補者数・有権者数などを引数に、9 種類の選挙・比例ブロック（複数県）・合区・
  全国区を含む選挙データを生成する（同じ `--seed` なら同じデータ）。生成後に `seed` の検証を通す。`--check DIR` で、
  手で編集した既存のデータの検証だけを行える。
- **依存の追加**: `csv` 1.4.0（追加時点の最新の安定版。CSV の読み書き。引用符・改行・BOM を正しく扱うため自前で書かない）。
- **確認スクリプト・計測**: `scripts/lib_seed.sh` が、小さなデータを seedgen で生成する。確認スクリプトは、名簿の有権者
  `voter-N` の N 番目の投票用紙へ投票する。bench は、名簿の有権者 × その投票用紙から「投票計画」を作る（尽きたら止まる）。

## 理由
- 表計算ソフトで編集できる CSV にすれば、件数が多くても、非エンジニアがデータを直せる。
- 読み込み時に、ファイル・行つきで検出すれば、誤ったデータで選挙が始まる前に直せる。
- 名簿を起動時に読み込めば、api はステートレスのまま（状態は持たず、読み取り専用のキャッシュだけ）。
- 順番の固定を画面の `flow`（純粋関数）に持たせれば、通常の `cargo test` で、折り返さないことまで検証できる。

## 代替案
- **JSON Schema**: 上述のとおり、ファイル間の整合を検査できない。
- **サーバも、先頭の未投票以外への投票を 409 で拒否する**: 順番の強制が、画面とサーバの二重になる。今回は、画面の
  固定 + 表示順の一覧で足りるとした（将来の要件次第で追加できる）。
- **名簿を今すぐ DB に置く**: テーブル・投入ツール・DB モードの起動手順が増える。認証の DB 化と合わせて行う。
- **名簿にない有権者のログインを拒否する**: stub 認証（原則 7）の「入力 ID を採用する」を崩す。認証と名簿の判定は別にした。
