# 0013: ID を文字列コードにする（チェーンの形式の版 2・DB スキーマ）

## 背景
選挙・選挙区・投票用紙・候補者の ID は、`u32` の連番だった（票の正規化形式は `ballot_id(16) ‖ contest_id(4) ‖
candidate_id(4)` の固定長 24 バイト）。47 都道府県・複数の選挙の種類・大量の候補者を扱うには、区割りの変更や候補者の
追加で意味が変わる連番ではなく、**変更されない文字列コード**が要る（CLAUDE.md の原則 13）。合区のように、1 つの選挙区が
複数の都道府県にまたがる場合も、ID は変えずに表せなければならない。

## 決定
- **ID 体系**（`crates/domain/src/ids.rs`。検証つきの文字列型。読み込み時にすべて検証する）:
  `election_id`（`2026-general`）、`election_type`（`shugiin_smd` など）、`district_id`（`shugiin_smd.13.01`。先頭の
  セグメントが選挙の種類）、`contest_id` = `{election_id}/{district_id}`、`candidate_id` = `{district_id}.c{連番}`。
  文字種は小文字の英数字・`_`・`-`（区切りは `.` と `/`）。最大長は election_id 32・election_type 32・district_id 64・
  contest_id 97・candidate_id 80（連番は 1 以上・先頭に 0 を付けない・最大 14 桁。桁数は固定しない）。
- **都道府県は選挙区の属性**（`prefectures`。JIS X 0401 の 2 桁コードのリスト）。合区・比例ブロックも、ID は変えず、
  リストで表す。**意味が将来変わり得る情報（都道府県・区割り）は ID に埋め込まない。**
- **票の正規化形式（ブロックの形式の版 2）**: `ballot_id(16) ‖ len(contest_id)(2) ‖ contest_id ‖ len(candidate_id)(2) ‖
  candidate_id`。ID は ASCII のバイト列で、長さは 2 バイトの固定幅・ビッグエンディアン（最大 197 バイト）。
  ヘッダ（86 バイト）とハッシュのタグは変えず、`version` を 1 から 2 に上げた。原則 4 の「固定長ビッグエンディアン」は、
  「固定幅の長さ接頭辞つきのビッグエンディアン」に読み替える（serde / JSON でハッシュ対象を作らない点は同じ）。
  長さ接頭辞が先頭にあるので、フィールドの境目は曖昧にならない（別の票が同じバイト列にならない）。
- **DB スキーマ**: `participation.contest_id`・`ballot_pool.contest_id / candidate_id` を `text` に、`blocks.ballots` の
  tuple を `<blob, text, text>` にした。**旧いスキーマ・旧いチェーン（版 1）とは互換性がない**ので、接続時に
  `system_schema.columns` で `participation.contest_id` の型を確認し、旧いときは、キースペースの作り直しの手順つきで
  失敗させる（実行時に型が合わずに失敗するのを避ける）。
- **`Ballot` は `Copy` ではなくなる**（ID が `String`）。所有権を移す箇所は `clone` を明示する。
- 監査用の集計（`/audit/counts`・verifier の突合）も、`contest_id` の文字列で行う。投票用紙が数千枚になるので、突合は
  ID で引ける索引（`HashMap`）を使い、verifier は、件数が多いときは不一致の行だけを表示する。

## 理由
- 文字列コードは、区割りの再編・候補者の追加・選挙の追加で変わらず、人が読める（監査で票の集計先が分かる）。
- 長さ接頭辞つきにすれば、固定長のパディング（最大長 × 2 の無駄）を避けつつ、正規化の一意性を保てる。

## 代替案
- **内部は数値のまま、文字列との対応表を持つ**: 対応が読み込み順で変わり、チェーンに書いた番号の意味が失われる。却下。
- **ID をハッシュ（32 バイト）にして、固定長を保つ**: 票から投票用紙・候補者を読み取れず、監査（投票用紙別の突合）が
  対応表に依存する。却下。
- **最大長までゼロ埋めして固定長にする**: ブロック・DB・API の 1 票あたり 190 バイト以上の無駄が、全票に付く。却下。
- **DB に、旧いデータを新しい形式へ移す移行を用意する**: 旧いチェーンは署名・ハッシュが版 1 の形式で、変換すると
  ハッシュが変わる（チェーンの意味が失われる）。プロトタイプなので、作り直しを選んだ。
